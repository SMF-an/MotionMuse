# MotionMuse 演奏优先页面设计

## 目标

将 `web/app.html` 作为应用主页面。用户进入后优先看到实时演奏舞台；普通板四角标定只在第一次开始演奏、切换输入源或板子追踪丢失时出现。

## 主页面

- 左侧为实时画面主舞台，占页面主要面积；显示摄像头/视频画面、板子四边形、和弦区、扫弦带和手部骨架。
- 舞台左上显示当前和弦、最近一次扫弦方向和力度；右下显示板子追踪状态、特征点数与 FPS。
- 右侧为紧凑的演奏控制台：演奏状态、当前乐器、动作检测状态、结束演奏、切换输入与重新标定。
- 首次完成输入选择后，若无有效板子配置，主舞台显示半透明四角标定覆盖层；完成后覆盖层消失并自动启动演奏。

## 标定与异常状态

- 标定仅是覆盖在主舞台上的准备步骤，不单独占据页面。
- 四角按左上、右上、右下、左下采集，生成同现有格式的 `board_calibration.json`。
- 跟踪正常时不显示标定引导，只保留“重新标定板子”按钮。
- 当连续帧追踪失败时，暂停和弦/扫弦事件，在舞台中央显示“板子丢失，请重新标定”，保留视频画面。

## 状态流

```text
选择输入 → [无标定] 舞台内四角标定 → 演奏中
    ↑                 ↓                 ↓
切换输入 ←──────── 重新标定 ←──── 追踪丢失
```

## 验收条件

- 用户打开页面时不会首先看到标定表单或单独标定页。
- 完成标定后，摄像头/视频画面持续显示且自动进入手部识别。
- 演奏中能看见当前和弦、扫弦反馈、手部骨架和板子追踪状态。
- “重新标定”不离开主页面，且不改变输入源。
- 追踪丢失后不会继续触发演奏事件。
