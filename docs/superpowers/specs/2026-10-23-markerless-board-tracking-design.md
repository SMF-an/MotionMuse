# MotionMuse 无标记板子稳健追踪方案

状态：待按本文采集小规模数据并验证；不是现有系统已达到的性能说明。本文针对普通、无 ArUco 标记的长方形板子，保留现有 ArUco 模式作为对照和演示备份。

## 1. 目标与边界

用户拿起一块未专门设计的平面长方形板子，启动前指定一次“琴颈端”和“琴身端”（或点击四角）；之后板子平移、旋转、短时被双手遮挡时，演奏区应随板子移动。识别失去依据时必须显示“定位不可靠”并暂停触发新和弦/扫弦，不能把漂移的区域当作有效结果。

“任意板子”在第一阶段具体指：外形可辨的硬质平面长方形板，四边大致笔直，在摄像头中可见尺寸至少约 120 像素短边，通常至少部分板面/边缘可见。纯色无纹理板、与背景同色、强反光、严重运动模糊、长时间完全遮挡，单目 RGB 摄像头不能保证持续精确定位；模型也无法凭空恢复完全不可见且无运动约束的目标。需要通过实测确定各条件的可用范围，而非承诺所有板子都可靠。

## 2. 推荐模型及原因

首版只训练一个轻量四角关键点模型，并使用传统视觉与时间连续性校验结果。分割模型暂不进入采集、标注和实时推理主流程；若单模型评估暴露出特定失效场景，再根据失败案例决定是否补做分割对照。

| 模块 | 首选 | 输出与作用 | 何时考虑替换 |
| --- | --- | --- | --- |
| 板子检测与四角 | `yolo11n-pose.pt` 微调，1 个 `board` 类别、4 个几何角点 | 一次输出板框与四个角点；依据角点直接计算板面单应性和演奏区 | 未见板子/遮挡测试不达标时先补数据或试 `yolo11s-pose.pt`，再评估是否需要分割模型 |
| 几何/身份校验 | OpenCV ORB 或 AKAZE 特征 + RANSAC 单应性 | 对有纹理的板子，把当前帧与可信参考帧匹配；阻止逐帧位姿累积漂移 | 纯色板特征不足时不能强行用该通道，以关键点几何和可信历史位姿为主 |

[Ultralytics YOLO11 官方文档](https://docs.ultralytics.com/models/yolo11)列出 `yolo11n-pose.pt` 并支持训练、验证和导出。选择 Nano 版是为了先建立可在 Xavier NX 上验证的轻量基线，**不是**已有 NX 帧率保证。关键点模型一次输出板框和四个角点；定位质量通过关键点置信度、凸四边形几何约束、锚帧特征匹配和时间连续性共同校验。分割模型未来可作为可选对照，不是首轮数据集的必要标注目标。

模型权重与训练所用 Ultralytics 版本需固定；公开发布前核查其许可证要求。

## 3. 数据采集计划

### 首轮规模

- **16 块不同板子**：不同尺寸、厚度、颜色、纹理和反光程度；至少包含纯色/低纹理板、包装板、书本或文件夹等。避免只用同一块板子换背景冒充新板子。
- 每块板录 **4 段约 30 秒**，以实际使用的 Logitech 摄像头为主。总计约 **32 分钟视频**，30 FPS 时约 5.8 万原始帧；这不是需要逐帧标注的数量。
- 每块板从四段中抽 **约 150 帧**，首轮约 **2,400 张带板标注图**；另取 **300–500 张无板/干扰物负样本**。相邻帧不密集重复标注：先均匀抽样，再加抽遮挡开始/结束、快速转动、出入画、模糊和重新捕获瞬间。
- 按**板子 ID**划分：10 块训练、3 块验证、3 块测试，约为 1,500 / 450 / 450 张带板图。来自同一板子的所有视频只进入一个集合；同一场景的紧邻帧也不能跨集合。测试集直到模型和阈值确定前不参与调参。

四段的动作定义如下：`slow` 为完整入镜、少遮挡的慢速平移/旋转，测基础定位；`performance` 为自然演奏姿势和手部和弦/扫弦动作，测日常遮挡；`fast` 为板子仍在视野内的快速平移、转动和突然停顿，测模糊与快速重定位；`occlusion` 为板子基本静止，手/前臂依次遮挡一个角、相邻两个角和部分边缘，再露出，测遮挡与恢复。完全遮挡或出画只用于评估丢失与重新捕获，不要求模型在目标不可见时输出位置。采集者不需要逐段填写场景和光照参数，应主动轮换背景、拍摄位置与光照条件，避免同一块板的四类视频都在同一环境中完成。全数据集另包含不同衣服/肤色、板子与背景颜色接近、多人或另有长方形物体、桌面/手持、不同距离和左右手持板。记录摄像头分辨率、曝光设置、板子 ID、动作与遮挡类别；如有特殊环境情况可另记在采集日志中。优先改善照明和快门造成的运动模糊，因为无法辨识的原始帧不适合靠模型“补救”。

上述是**验证性起步量**，不是通用泛化所需的确定数字。若未知板子测试明显劣于已见板子，第二轮扩充到约 25–40 块板、6,000–10,000 张有选择的标注帧，优先补最差的板面材质/遮挡/背景组合，不是简单增加连续相似帧。

## 4. 标注规范

标注关键点模型需要的板框和四角，不画板面掩膜。每条记录包含 `frame_id`、`video_id`、`board_id`、图像宽高、是否有板、目标板实例、四角坐标及可见性、遮挡/模糊/截断标志。若画面出现多个板子，只标当前演奏板并对干扰板另记身份，不能混成一个实例。

四角标注**只描述板子的几何形状**，不标注琴颈区、琴身区或演奏区域。四点统一命名为 `1、2、3、4`：编号 `1` 是该板固定的起始角，`2`–`4` 沿板周界顺时针排列；同一块板的所有视频保持相同编号。模型只负责预测四个几何角点。运行时首次标定再由用户指定哪条短边是琴颈端；程序据此建立板子坐标系，并按预设比例计算琴颈/和弦区与琴身/扫弦区。对于外观对称、没有方向线索的板子，视觉本身无法判断哪端是琴颈，因此该方向选择必须由用户完成。前端显示镜像时，角点坐标统一在原始摄像头帧中计算，绘制时才镜像。

每个角记录 `x,y,visibility`：`2` 为肉眼可见；`1` 为被遮挡但能依据同段前后清晰帧和板的几何关系可靠推断；`0` 为不可可靠标注。`visibility=0` 时不给虚构坐标，转换器按选定训练框架的约定处理或排除该实例的四角损失。板子部分出画同理。标注员不得仅凭“大概是矩形”随意填隐藏角；被挡角可用相邻清晰帧与单应性插值生成初值，再人工复核。四角模型对隐藏角的可学性必须通过单独遮挡测试验证，不能因为标签写了 `1` 就视为解决。

四角编号只表示板子的几何角点，按板自身固定的 `1–4` 顺时针顺序标注，不赋予琴颈端/琴身端语义。首次演奏标定时由用户指定琴颈端，程序再按板坐标划分和弦区与扫弦区。每个点记录 `x,y,visibility`；`visibility=0` 时不虚构坐标，转换器按训练框架约定处理或排除该实例的关键点损失。板子部分出画同理。被挡角可用相邻清晰帧和板几何关系生成初值，再人工复核；模型是否能可靠预测隐藏角必须通过独立遮挡测试验证。关键点格式使用 `kpt_shape: [4, 3]`。训练增强先关闭会改变角点语义的水平/垂直翻转，待实现正确的角点重映射后再启用。

每批随机抽至少 10% 双人复核：检查角点顺序、镜像和遮挡角是否有可靠依据。分歧样本仲裁后才进入训练集。

## 5. 训练、定位与状态机

先在开发机 GPU 上微调 `yolo11n-pose.pt`，输入边长从 640 起试，并保留权重、数据版本、随机种子和训练配置。与现有无标记轮廓算法及锚帧特征匹配做对照。训练集可做亮度、色偏、轻度透视、模糊和**真实形状**的手部遮挡增强，但合成遮挡不能替代真实演奏视频；验证/测试不用增强。

每帧处理顺序：

1. 从同一原始帧获取四角模型与手部结果。板框用于检测目标，手部区域从特征匹配中排除。
2. 对校准时或最近一次**高可信**帧保存板面参考图与特征点。当前帧只与这些锚帧匹配，RANSAC 求单应性；不得把上一帧预测结果不断写回参考图。ORB/AKAZE + 单应性的依据见 [OpenCV 平面目标追踪教程](https://docs.opencv.org/4.10.0/dc/d16/tutorial_akaze_tracking.html)。特征数量少或内点只挤在一小块时，此通道标记为不可用。
3. 比较关键点模型、特征单应性投影角点和上一可信位姿。检查关键点置信度、凸性、面积、长宽比、角点重投影误差、特征内点数量及空间分布、与上一可信位姿的运动幅度；每项分别记录，不用一个模型置信度代替整体可信度。冲突时拒绝更新锚帧，不能按高分结果强行覆盖。
4. 状态分为 `UNINITIALIZED → TRACKING ↔ OCCLUDED → LOST → REACQUIRING → TRACKING`。短遮挡只从最后可信位姿做有时限的运动预测，随着时间增大不确定性；预测位姿不能刷新参考锚，也不能无限续期。完全遮挡或多路证据冲突进入 `LOST`，暂停新扫弦/和弦事件，保留视频画面并显示原因。重新出现后依赖全图检测与锚帧匹配重新捕获，不把旧预测位置当唯一搜索窗口。
5. 仅在 `TRACKING` 且定位可信时，把四角单应性传给现有演奏区映射。前端视频、四角、手和弦/扫弦状态必须绑定同一 `frame_id` 或时间戳；现有 MJPEG 画面与状态接口若异步显示，需要先解决对齐，否则可能误判为定位漂移。

阈值（例如重投影误差、允许遮挡时长）先在验证集上按板子短边归一化后调节，再冻结并在测试集验证；不预先把某个阈值写成“普适正确”。近乎无纹理的板子可能没有有效特征通道；此时只能依靠四角/轮廓和更保守的状态判定，不能声称达到与有纹理板同等精度。

## 6. 评估与验收

除普通图像精度，还要按完整视频评价，尤其统计**错误地显示为可信**的帧：

| 指标 | 测法 | 首轮建议验收门槛（待实测确认） |
| --- | --- | --- |
| 四角精度 | 每角误差除以真实板子短边像素长度，分别统计可见/遮挡角 P50、P95 | 正常演奏帧 P95 ≤ 5%；重遮挡帧单列，不掩盖失败 |
| 稳定性 | 连续录制 3–5 分钟；有效跟踪时间、每分钟丢失次数、重新捕获耗时和最大漂移 | 正常演奏有效时间 ≥ 90%；短遮挡后中位恢复时间 ≤ 0.5 秒 |
| 安全性 | 板子完全遮挡、移出画面、出现相似长方形物体 | 错误高可信定位和由此触发的误扫弦均需逐例记录；目标为 0 次误触发 |
| 实时性 | Xavier NX 上包含摄像头、Pose 模型、特征匹配、手部识别、网页呈现的端到端测量 | 目标 ≥ 15 FPS、动作到声音延迟 ≤ 150 ms；仅模型推理 FPS 不算通过 |

门槛是项目设计目标，**不是当前已测性能**。评估按板子、场景、遮挡比例、快速运动、低纹理/反光分别出表；比较旧轮廓法、四角模型单用、四角模型加锚帧匹配的结果。若几何与锚帧校验没有降低错误高可信率，就不能因为界面看起来更平滑而宣布成功。达到目标后再用至少 3 块全新板做演示前盲测。

## 7. Xavier NX 部署及实施顺序

先在 NX 上确认 JetPack、Python、OpenCV、TensorRT 版本与可用显存/功耗模式，再导出并测试 TensorRT FP16；不要把开发机训练环境直接复制到 NX。[NVIDIA JetPack 5.1.3 发布说明](https://docs.nvidia.com/jetson/jetpack/5.1.3/release-notes/index.html)列出 Xavier NX 支持及 Ubuntu 20.04 基础系统。当前项目 `pyproject.toml` 要求 Python ≥ 3.13，可能不适配板上现成环境；这应作为**部署前兼容性关卡**处理，不能等模型训练完才发现。精度与速度不足时先分别测试输入尺寸、模型频率、视频分辨率和异步流水线；INT8 量化须另用代表性校准集验证遮挡场景误差。

建议三人分工并行但按共同数据规范协作：A 负责采集和角点标注质检，B 负责关键点模型训练与评估，C 负责锚帧融合、状态机、网页对齐及 NX 测试。预计 6 周：第 1 周制定并试标规范、录小样；第 2 周采集和标注首轮数据；第 3 周训练 Pose 基线并纠正标签问题；第 4 周做锚帧匹配与可信度融合；第 5 周接入现有演奏链路；第 6 周 NX 优化、盲测及失败案例复盘。第 3 周末若未见板子测试表现不够，先补数据或调整关键点方案；第 6 周未过安全/实时门槛，则演示继续用 ArUco 模式，同时把无标记模式标注为实验性。
